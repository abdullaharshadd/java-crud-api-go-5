- [info] **inconsistent-pattern**: The Allow header is built two different ways in the same package. For OPTIONS, allowMethod in handler.go joins the methods with "," ("GET,HEAD,OPTIONS"). For 405 responses, writeError in errors.go joins the same MethodNotAllowedError.Allowed list with ", ". So clients get different header formats for the same route depending on the request method. Spring builds both with the same comma-only formatting. Pick one separator and use it in both places.
- [info] **inconsistent-pattern**: The HTTP layer logs through two different loggers. Handler takes a zerolog.Logger through NewHandler and uses h.log. writeError and writeJSON in errors.go use the package-global github.com/rs/zerolog/log instead. As a result, any fields or level set on the injected logger don't apply to error and 500 logs. Those are the logs that matter most when diagnosing failures. Use the injected logger in errors.go too, for example by making writeError a method on Handler or passing the logger in.
